## The fix

I closed requirement 4 by giving the editor **one legality rule with two callers**. `applyConstraints()` was doing two jobs — *transforming* a candidate (min-extent → snap → clamp) and then *judging* it (bounds + rotated AABB + reserved regions). I extracted only the judging half into `illegalReason(s)`, which returns a human reason or `null`. The mouse reaches it through `applyConstraints()` (its step 5+6 is now a single `return illegalReason(c) ? null : c;`), and a file reaches it through `loadIR()`. There is now exactly one copy of the reserved-region check in `editor.js`.

All four defects are closed:

- **`makeEl()` with no check** — `loadIR()` pass 1 judges every element before `makeEl()` is reachable.
- **Stage cleared before elements were looked at** — `loadIR()` is now two passes: judge everything and throw, *then* clear/commit. "Reject the entire import" genuinely wasn't reachable from inside the old loop; it is from here.
- **The NaN trap** — `geometryIsReadable()` runs *first* inside the judge. Every comparison against `NaN` is false, so a missing `x` would otherwise sail through a perfectly correct reserved-region check. `typeof` also rejects `true` and `"100"`, matching `validate.py::_num` on the backend side. I added one guard the brief didn't name for the same reason: a non-positive `w`/`h`, because an inverted box makes `elementBBox()` return `x2 < x1` and every downstream predicate then compares a backwards interval.
- **Unguarded `runs[0]` / `p.runs.map()`** — `stateFromIR()` and `paragraphsToHTML()` never throw and never repair.

The judge deliberately does **not** enforce `MIN_EXTENT`: `w >= 4` is drawing ergonomics, the schema's rule is `w > 0`. That's precisely why the transform had to be split off rather than having the import call `applyConstraints()` — snapping and clamping a hand-authored file would silently rewrite the user's deck on load.
