 256: # GATE 4b -- THE JSON IMPORT GOES THROUGH THE SAME GATE AS THE MOUSE
 257: # ===============================================================================================
 258: #
 259: # Requirement 4 says the reserved regions are STRICTLY ENFORCED IN THE JS. They were enforced
 260: # against the mouse (applyConstraints) and NOT against a file (loadIR): an element sitting on the
 261: # Vieworks logo could be imported, rendered, and reserialized, and it came back as a 422 the user
 262: # could not explain -- from a file this editor may itself have written before someone hand-edited
 263: # it. These tests are what make "there is exactly one door into the stage, and it is locked" a
 264: # checkable sentence instead of a claim in a comment.
 265: #
 266: # WHY THIS RUNS THE JS INSTEAD OF GREPPING IT
 267: # [REDACTED]
 268: # Gate 1 (test_editor_source.py) is deliberately a grep, and says so. A grep cannot tell you that an
 269: # element on the header is actually REFUSED -- only that some words appear in the file. So this
 270: # section EXECUTES the shipped rule. It does not re-implement it in Python: a Python copy of
 271: # illegalReason() would be a third source of truth, and the entire bug being fixed here is what
 272: # happens when the rule exists in more than one place.
 273: #
 274: # The functions below are lifted VERBATIM out of editor.js by name and run in Node. Only the DOM
 275: # around them is stubbed (stage, makeEl, titleField...), because the DOM is not what is under test:
 276: # the judge and loadIR()'s ordering are. If node is not installed these tests SKIP -- `pytest tests/`
 277: # must stay green for someone who installed only the renderer -- so the never-skipped structural
 278: # assertions at the bottom hold the same invariants a second way.

 321: def _js_decl(name: str) -> str:
 322:     """The text of `var <name> = ...;` -- up to the first `;` at bracket depth 0."""
 323:     start = EDITOR_SRC.index(f"var {name} = ")
 324:     depth = 0
 325:     for i in range(start, len(EDITOR_SRC)):
 326:         ch = EDITOR_SRC[i]
 327:         if ch in "([{":
 328:             depth += 1
 329:         elif ch in ")]}":
 330:             depth -= 1
 331:         elif ch == ";" and depth == 0:
 332:             return EDITOR_SRC[start : i + 1]
 333:     raise AssertionError(f"editor.js: `var {name} = ...` is never terminated")
 334: 
 335: 
 336: def _js_function(name: str) -> str:
 337:     """The text of `function <name>(...) {...}`, braces balanced.
 338: 
 339:     Same technique as Gate 1's _function_body, and it carries the same (satisfied) assumption: none
 340:     of the extracted functions contains a brace inside a string, a comment or a regex literal.
 341:     """
 342:     start = EDITOR_SRC.index(f"function {name}(")
 343:     depth = 0
 344:     for i in range(EDITOR_SRC.index("{", start), len(EDITOR_SRC)):
 345:         if EDITOR_SRC[i] == "{":
 346:             depth += 1
 347:         elif EDITOR_SRC[i] == "}":
 348:             depth -= 1
 349:             if depth == 0:
 350:                 return EDITOR_SRC[start : i + 1]
 351:     raise AssertionError(f"editor.js: unbalanced braces in {name}()")

 354: # The DOM, stubbed. loadIR() is allowed to touch exactly these, and every one of them RECORDS what
 355: # was done to it -- which is how "the stage was never touched" becomes an assertion and not a hope.

 268: ## 5. Frontend architecture ??HTML/JS
 269: 
 270: ### 5.1 Technology choice: DOM + inline SVG. **Not `<canvas>`. Not Fabric.js.**
 271: 
 272: Fabric is a `<canvas>` library. Text becomes bitmap-rendered by *Fabric's own* layout engine, which means (a) you reimplement text editing from scratch, and (b) Fabric's wrapping metrics become a **third text engine**, agreeing with neither the browser nor PowerPoint. For a project whose headline risk is text overflow, adding a third metric model is a bad trade.
 273: 
 274: The DOM gives you, free:
 275: - `contenteditable` ??real text editing, nothing to reimplement;
 276: - **real browser metrics in the real Century Gothic** ??the closest possible preview of what PowerPoint will do;
 277: - the element *is* the model (`el.dataset.x`), so serialization is trivial.
 278: 
 279: Total library requirement: **interact.js (~10 KB)** for drag/resize handles and snapping ??or ~150 lines of `pointerdown`/`pointermove`/`pointerup` with pointer capture. Nothing else.
 280: 
 281: ### 5.2 Canvas sizing and the coordinate system
 282: 
 283: **The model space is 960 횞 540 logical units, and nothing else ever enters the IR.**
 284: 
 285: ```
 286: 1 logical unit  ?? 1 pt  ?? exactly 12,700 EMU        (12192000/960 = 6858000/540 = 914400/72)
 287: ```
 288: 
 289: Consequences that delete whole bug classes before they exist:
 290: - Geometry: `emu = round(u * 12700)` ??integer, exact.
 291: - **Font size maps 1:1** ??a size-14 run is `Pt(14)`. No scale factor anywhere. (1280횞720 also divides exactly, at 9525 EMU/px, but then every font size needs a 횞0.75 factor. 960횞540 is strictly better.)
 292: 
 293: **Decouple model space from display.** The stage is a `960 횞 540` div in *logical* units; zoom is a single `transform: scale(s)` with `transform-origin: 0 0`.
 294: 
 295: ```css
 296: #stage {
 297:   position: relative;
 298:   width: 960px; height: 540px;          /* 1 CSS px == 1 logical unit at s = 1 */
 299:   transform: scale(var(--zoom));
 300:   transform-origin: 0 0;
 301:   background: #FFFFFF;
 302:   overflow: hidden;
 303: }
 304: ```
 305: 
 306: **The zoom-inversion rule (critic rule 7), stated once and obeyed everywhere:**
 307: 
 308: ```js
 309: // The ONLY place a device coordinate becomes a model coordinate.
 310: function toModel(ev) {
 311:   const r = stage.getBoundingClientRect();   // used ONLY for pointer inversion
 312:   return { x: (ev.clientX - r.left) / zoom,  // `zoom` is the single source of truth
 313:            y: (ev.clientY - r.top)  / zoom };
 314: }
 315: ```
 316: 
 317: **Forbidden in the IR path, without exception:** `getBoundingClientRect()` widths/heights, `offsetWidth`, `clientWidth`, `devicePixelRatio`, responsive/percentage widths, any value read back from computed CSS. Geometry lives in JS state (`el.dataset.x/y/w/h`), and CSS is written *from* that state, never read back into it. `getBoundingClientRect()` appears exactly once, in `toModel()`.
 318: 
 319: Round only at the final `logical 횞 12700` conversion ??carry floats in the IR, round in Python.
