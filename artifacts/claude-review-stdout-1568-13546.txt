````markdown
## The design: one legality rule, two callers

### Step 1 — extract the legality rule out of `applyConstraints()`

`applyConstraints()` today does two different jobs in one function: it **transforms** a candidate
(min-extent, snap, clamp-into-slide) and then it **judges** it (bounds + reserved regions, lines
232-237). Only the judging half may be reused by the import path. Split it:

   *
   * THE single definition of "this box is legal". applyConstraints() consults it for the mouse;
   * importProblems() consults it for a file. There is no third answer to this question anywhere in
   * this file, because a second copy is a copy that will drift from geometry.py.

  function geometryProblems(s) {
    var problems = [];
    var box = elementBBox(s);
    if (outOfBounds(s)) {
      problems.push('falls outside the ' + CANVAS.w + 'x' + CANVAS.h + ' slide -- its bounding ' +
                    'box is (' + box.map(round6).join(', ') + ')' +
                    (s.rot && s.rot % 360 !== 0 ? '. That is the ROTATED footprint.' : '.'));

The rules, in order. Every one of them appends to the list; **none** of them returns early except

1. **Payload shape.** `ir` is a non-null object; `ir.schema === SCHEMA`; `ir.canvas` exists with

   rescaled"). `ir.title`, if present, must be a string. If `ir` is not an object, or `ir.elements`

## Three things NOT to do

1. **Do not run imported elements through `applyConstraints()`.** It is tempting — it is right there
   and it returns `null` for illegal input. It also **snaps to the 4-unit grid, bumps `w`/`h` up to
   `MIN_EXTENT`, and translates the box back inside the slide**. Feeding a *legal* imported deck
   through it silently moves the user's elements, and it breaks the Gate 4 contract: download JSON →
   load JSON → export must be the same deck, not a re-snapped approximation of it. The import path
   **judges and refuses**; it never transforms. That is the whole reason step 1 splits the function.
2. **Do not enforce `MIN_EXTENT` (4) at import.** The schema says `exclusiveMinimum: 0`
   (`schema.json:191`); 4 is the *editor's* authoring floor, not the format's. A hand-authored or
   CLI-produced deck with a 2-unit hairline band is a legal `canvas-ir/1` payload, and refusing to
   open it would make the editor stricter than the renderer it is a front end for. Require `> 0`.
   (A sub-4 element does get bumped to 4 the first time the user drags it. That is the pre-existing
   behaviour of `commit()`; do not change it.)
3. **Do not touch `nextId()`.** It already loops until `stage.querySelector('.el[data-id="..."]')`
   comes back empty, so an imported `el7` cannot be reissued even though `idSeq` never advanced. It
   looks like a bug. It is not one. Leave it.

import json
import shutil
import subprocess

NODE = shutil.which("node")
needs_node = pytest.mark.skipif(NODE is None, reason="node is not on PATH")

FIXTURES = Path(__file__).resolve().parents[1] / "fixtures" / "canvas"

# Pulled VERBATIM out of editor.js -- never re-declared here. A number typed twice is a number that
# will disagree with itself.
NEEDED_CONSTS = ["SCHEMA", "CANVAS", "EPS", "HEADER_RESERVED", "FOOTER_RESERVED", "REJECT_REGIONS",
                 "SHAPE_TYPES", "FORBIDDEN_COLOR"]
NEEDED_FUNCS = ["round6", "isNum", "intersects", "elementBBox", "outOfBounds", "geometryProblems",
                "importProblems"]


def _var_statement(src: str, name: str) -> str:
    """`var NAME = ...;` -- bracket-balanced, so an array or an object literal comes back whole."""
    start = src.index(f"var {name} = ")
    depth = 0
    for i in range(start, len(src)):
        ch = src[i]
        if ch in "([{":
            depth += 1
        elif ch in ")]}":
            depth -= 1
        elif ch == ";" and depth == 0:
            return src[start : i + 1]
    raise AssertionError(f"unterminated `var {name}` in editor.js")


def _function_source(src: str, name: str) -> str:
    start = src.index(f"function {name}(")
    return src[start : src.index("{", start)] + _function_body(src, name)


def import_problems(ir: dict) -> list[str]:
    """editor.js's OWN importProblems(), executed. Not a Python re-implementation of it."""
    script = "\n".join(
        [_var_statement(EDITOR, c) for c in NEEDED_CONSTS]
        + [_function_source(EDITOR, f) for f in NEEDED_FUNCS]
        + [f"const ir = {json.dumps(ir)};",
           "console.log(JSON.stringify(importProblems(ir)));"]
    )
    # check=True on purpose: if importProblems() grows a dependency that is not in NEEDED_*, node
    # dies with a ReferenceError and this test goes RED. It never degrades to a silent pass.
    out = subprocess.run([NODE, "-e", script], capture_output=True, text=True,
                         encoding="utf-8", check=True)
    return json.loads(out.stdout)


def load_fixture(name: str) -> dict:
    return json.loads((FIXTURES / f"{name}.json").read_text(encoding="utf-8"))
```
````

Substantive notes on what I found while reading the code, beyond the critic's report:

The critic named one hole; there are really four, and two of them would survive a literal fix. The most dangerous is that `read()` coerces with `+d.x`, so a missing coordinate becomes `NaN` — and since every comparison against `NaN` is false, `outOfBounds()` and `intersects()` both return `false`. Add the geometry check the critic asked for without also guarding the numbers and an element with no `x` still lands on the logo. The second is that `loadIR` clears the stage and overwrites the title *before* it looks at any element, so "reject the entire import" is unachievable without moving the gate ahead of the first DOM mutation.

The one design decision worth flagging to the orchestrator: the brief forbids reusing `applyConstraints()` on imported elements even though it would be the shortest fix. It snaps, applies the 4-unit minimum extent, and translates boxes back into the slide — so it would silently rewrite a *legal* imported deck and break the Gate 4 download-then-reload round trip. Hence the split into a pure `geometryProblems()` judge shared by both callers.

For the regression tests the critic demanded, the existing fixtures (`reject_header`, `reject_footer`, `reject_rotated_into_header`, and crucially `edges.json`, whose elements sit flush at y=92/y=500) already cover both directions, and the pure validator can be executed for real under Node (v24.14.0 is installed) by extracting it from `editor.js` with the `_function_body()` helper that test file already has — no npm, no jsdom.
