The repair is in. Here's what happened.

## What I changed

**`editor.js`** — four sites, mirroring `loadIR()` as the brief instructed:

1. **New `unrestorableReason(snap)`**, directly below `illegalReason()` (`editor.js:265`). It applies the existing judge to every record in a snapshot, collects *all* problems, and returns a reason or `null`. It transforms nothing and touches no DOM — which is what makes it safe to run before the stage is cleared.
2. **`restore()`** is now two passes: judge, then commit. The preflight sits **above `stopEditing()`**, not below it — `stopEditing()` mutates the DOM and calls `endTx()`, so it was itself a DOM touch happening before any element had been looked at. `restore()` now returns `true`/`false`, because all-or-nothing only works if the caller can tell which happened.
3. **`undo()`/`redo()`** peek instead of popping as the argument. `restore(past.pop())` took the entry off the stack *before* `restore()` ran, so a refusal or a throw destroyed the stage and the only snapshot that could restore it. That was the one defect needing no inductive argument, and it's the one I'd call a genuine data-loss bug.
4. **The claim at `editor.js:193`** now names all three writers instead of two.

**`test_app.py`** — eleven new tests plus an extension of the existing `test_makeEl_is_never_reached_without_a_verdict` to cover `restore()`, the call site that was the bypass. The behavioural ones lift `unrestorableReason()` out of `editor.js` and run it in Node **with no stubs at all**, so any reach for the DOM is a `ReferenceError` rather than something I merely assert.
