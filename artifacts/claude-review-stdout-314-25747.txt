## The design

### Step 1 — one preflight function, next to the judge

Add it directly below `illegalReason()` (i.e. after `editor.js:263`), so the rule and its second
caller sit in one place. It **reads and returns; it mutates nothing and it touches no DOM**.

```js
/* THE THIRD CALLER OF THE JUDGE.
 *
 * A snapshot is not a trusted input just because this editor minted it. Every element on the stage
 * was judged on the way in -- today, by commit(), loadIR() and duplicateSelected(), and therefore a
 * snapshot of that stage is legal by induction. The induction holds only until someone adds a fourth
 * writer, and when it breaks, it breaks HERE: undo would reintroduce an illegal element, the stage
 * would look fine, and the export would 422 with no way to explain it. The judge is cheap and inert.
 * Ask it.
 *
 * ALL OR NOTHING, and in this order: judge every element FIRST, touch the stage SECOND -- the same
 * order, and for the same reason, as loadIR().
 */
function illegalSnapshotReasons(snap) {
  if (!snap || typeof snap !== 'object' || !Array.isArray(snap.els)) {
    return ['the snapshot is not a snapshot'];
  }
  var problems = [];
  for (var i = 0; i < snap.els.length; i++) {
    var rec = snap.els[i];
    if (!rec || typeof rec !== 'object' || !rec.state || typeof rec.state !== 'object') {
      problems.push('els[' + i + ']: has no state');
      continue;
    }
    var why = illegalReason(rec.state);   // the ONE judge. Do not inline a second copy of the rule.
    if (why) {
      problems.push('els[' + i + '] (id "' + rec.state.id + '"): ' + why);
    }
  }
  return problems;
}
```

**Non-negotiable:** it calls `illegalReason()`. It does not re-implement bounds, rotated-AABB or
reserved-region checks, and it does not call `applyConstraints()` — snapping and clamping a snapshot
would silently rewrite the user's deck on undo, which is the same push-out you correctly refused for
the mouse and for the importer.

### Step 2 — `restore()` preflights, and reports whether it ran

`restore()` becomes two passes and returns a boolean. The preflight goes **above `stopEditing()`**.

```js
/* Returns true if the stage now holds `snap`, false if the snapshot was refused and the stage was
 * NOT TOUCHED -- not cleared, not retitled, not one element made. The caller must not pop until this
 * has returned true.
 */
function restore(snap) {
  /* PASS 1 -- JUDGE. Nothing below this line has touched the stage, and nothing above it may.
   * stopEditing() is a DOM mutation, so it belongs below this line too. */
  var problems = illegalSnapshotReasons(snap);
  if (problems.length) {
    setStatus(
      'That history step cannot be restored -- ' + problems.length + ' element(s) in it may not ' +
      'exist on this stage, so NOTHING was changed:\n' +
      problems.map(function (p, n) { return '  ' + (n + 1) + '. ' + p; }).join('\n')
    );
    return false;
  }

  /* PASS 2 -- COMMIT. Every state is legal, so this cannot fail half-way through. */
  stopEditing();
  ... the existing body, unchanged ...
  select(toSelect);
  syncProps();
  return true;
}
```

Everything from `stopEditing()` down stays **exactly as it is**. `makeEl()` + `appendChild()`, the
`innerHTML` restore, the `selected = null` before `select()`, the outright `syncProps()` call — all of
it is correct and all of it is load-bearing. You are adding a gate in front of a working function, not
rewriting one.

Keeping the preflight inside `restore()` (rather than only in the callers) is deliberate: it is the
function the critic named, it is the function `test_app.py:910` points at, and a fourth caller added
later is gated automatically instead of being one more place someone forgot.

### Step 3 — `undo()` / `redo()` peek, then pop

`pop()` moves below the restore. Nothing else about these functions changes.

```js
function undo() {
  if (!past.length) { setStatus('Nothing to undo.'); return; }
  endTx();                                  // a gesture may not straddle an undo
  var now = snapshot();                     // pure read -- safe before the restore, mutates nothing
  if (!restore(past[past.length - 1])) return;  // PEEK. Refused => stack and stage both untouched.
  past.pop();                               // ...only now is the step actually spent
  future.push(now);
  syncHistory();
  setStatus('Undo — ' + past.length + ' step(s) left.');
}
```

`redo()` takes the identical shape against `future` / `past`.

**The tradeoff, stated so you do not "improve" it:** a refused entry stays on the stack, so a poisoned
snapshot makes Ctrl+Z a no-op that keeps explaining itself rather than a key that works once and eats
the deck. Do **not** "recover" by discarding the entry — that is silently destroying the user's
history to hide a bug in the editor. A refusal here is not a user error; it is a defect report, and it
should be loud, repeatable, and non-destructive.
