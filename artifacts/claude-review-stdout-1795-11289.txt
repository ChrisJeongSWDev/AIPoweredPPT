## The review is done — here is what the strengthened brief adds

I reviewed `phase0_draft_brief.md` against `HTML_to_PPTX_Plan.md` §2/§4/§7/§9 and verified the plan's three self-flagged "never executed" recipes against the installed python-pptx 1.0.2 source. The substantive findings:

**A landmine the plan does not mention.** `Presentation.slides` is a property with a side effect — every access calls `rename_slide_parts()`, which resolves `related_part(rId)` for every rId still in `sldIdLst` (`pptx/presentation.py:111` → `pptx/parts/presentation.py:94`). Inside the deletion loop, between `drop_rel(rId)` and `sldIdLst.remove(sld_id)`, the package is transiently inconsistent. Any touch of `prs.slides` in that window — even `len(prs.slides)` in a debug print — dies with a bare `KeyError`. The loop must bind `sld_id_lst` once and never return to `prs.slides` until it finishes.

**The plan's drop-then-remove order is correct, and I can now say why.** `XmlPart.drop_rel()` pops the rel only `if self._rel_ref_count(rId) < 2`. At call time the `<p:sldId>` element still holds one `@r:id` reference, so the count is exactly 1 and the rel drops. Confirmed at `pptx/opc/package.py:409-430`.
