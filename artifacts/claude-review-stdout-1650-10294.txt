## Design notes / assumptions

- **Threshold interpretation** — "drags less than 5 units" is read as *the drag box is under 5 units on both axes*: `|dx| < 5 && |dy| < 5` → click-drop. A ≥5-unit reach on either axis is a real draw-out. This keeps a deliberate thin/wide drag working while treating a click (or a tiny wobble) as a drop.
- **Placement** — the dropped element's top-left is the click point (`o.x, o.y`); the connector is `x1,y1 → x1+100,y1+100`. Everything goes through the existing `applyConstraints(cand, { alt: true })`, so it is **not re-snapped** (a deliberate placement shouldn't jump) but is still **clamped into the slide** and judged by `illegalReason()` — exactly as the brief's out-of-bounds guidance requests. If it still can't fit (impossible for these default sizes on a 960×540 stage, but handled defensively), nothing is dropped and the status line says so.
- **One judge, one undo step** — the click-drop reuses `applyConstraints`/`makeEl`/`addEl` and pushes a single `ctx.before` snapshot (mirroring the draw-out path), so the reserved-region guarantee and undo semantics are preserved.
- **Auto-focus (requirement 2)** — a new textbox from *either* path is routed through `finishCreate → startEditing`, which does exactly what the old `dblclick` handler did (contenteditable attribute + `editing` class + `beginTx()` + `body.focus()`), now factored into one function so the two callers cannot drift.
