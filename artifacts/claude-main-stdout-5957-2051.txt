## The work

The brief was right that three of four requirements already shipped, so the real work was **undo/redo**. I built it snapshot-based rather than as inverse commands — raise/lower reorder the DOM, delete must remember its z-position, load replaces the whole stage, and each subtly-wrong inverse is a corruption that surfaces three undos later. A snapshot has one inverse and every mutation shares it. Crucially, restoring rebuilds through `makeEl()`, back down the same one-way state→CSS path, so undo *structurally cannot* reintroduce a device pixel.

Gestures are grouped (`beginTx` at drag start, push on first successful commit, drop at pointerup if nothing committed), so one drag is one step and a click-that-merely-selects costs nothing. A refused frame pushes nothing.

The panel moved to the right and hides when nothing is selected, scoped by `data-for` so a connector isn't offered a fill it can't serialize. **One real trap there**: `[hidden]` is specificity `(0,0,1,0)` and `#props label {display:flex}` is `(0,1,0,1)` — the ID selector wins, so a hidden label would be announced as hidden and still be painted and clickable. `#props [hidden]` at `(0,1,1,0)` fixes it, and a test pins it.

For `run.bold`/`run.italic`, the non-obvious part is that turning bold **off** must also strip `<b>`/`<strong>` from the body — bold comes from tags as well as the flag, so an "off" that only stopped *adding* bold would leave the text bold with the button un-pressed. And `stateFromIR` *summarises* the flag across all runs rather than reading the first one: the flag is OR-ed back into every run on export, so peeking at run one would make a deck with a single bold word re-export with the whole sentence bold.

Delete/Backspace and double-click I left alone, and added regression tests so Phase 2 can't quietly take them away.
