## 2. Phase 0, Step 1 ??the clean renderer template (blocking; do this first)

### 2.1 The problem

`Presentation("Vieworks_R&D_ppt_Template.pptx")` opens a deck that **already has 23 slides** (`layout_manifest.json` ??`deck.existing_slide_count: 23`). `add_slide()` appends a **24th**. Every export would ship all 23 exemplar slides, and the inherited page-number field on the new slide would read 24. The public `Slides` API has **no deletion operation**.

### 2.2 The fix

Build a **one-off, committed artifact**: `reference/renderer_template.pptx` ??same master, same 5 layouts, same theme, same `image5.jpeg` / `image2.svg` media, **zero slides**.

Slide deletion needs private API. That is acceptable **exactly once, in a build script**, and is forbidden in the request path (critic rule 3: *"Do not make private slide-deletion code part of each export request"*).

`src/aippt/tools/make_renderer_template.py`:

```python
"""One-off build step. Produces reference/renderer_template.pptx (0 slides).

Run once, commit the output, pin its SHA in reference/template_pin.json.
NEVER import this from the request path. NEVER overwrite the source template.
"""
import hashlib, json
from pathlib import Path
from pptx import Presentation
from pptx.oxml.ns import qn

SRC = Path("Vieworks_R&D_ppt_Template.pptx")
DST = Path("reference/renderer_template.pptx")
SRC_SHA = "[REDACTED]"


def sha256(p: Path) -> str:
    h = hashlib.sha256()
    with p.open("rb") as f:
        for chunk in iter(lambda: f.read(1 << 20), b""):
            h.update(chunk)
    return h.hexdigest()


def main() -> None:
    src_sha = sha256(SRC)
    if src_sha != SRC_SHA:
        raise SystemExit(f"source template changed: {src_sha}")

    prs = Presentation(str(SRC))          # SRC is never written back
    sld_id_lst = prs.slides._sldIdLst     # private, by necessity ??build step only
    for sld_id in list(sld_id_lst):
        rId = sld_id.get(qn("r:id"))
        prs.part.drop_rel(rId)            # drop the presentation->slide relationship
        sld_id_lst.remove(sld_id)         # drop the sldId entry

    DST.parent.mkdir(parents=True, exist_ok=True)
    prs.save(str(DST))

    out = Presentation(str(DST))
    assert len(out.slides) == 0, "slides survived"
    assert len(out.slide_layouts) == 5, "layouts lost"
    assert out.slide_width == 12192000 and out.slide_height == 6858000
    print(json.dumps({"source_sha256": src_sha, "renderer_sha256": sha256(DST)}, indent=2))
```

### 4.2 Startup verification ??`src/aippt/canvas/pin.py`

**Two gates, both mandatory, both at process start (not per request):**

```python
class TemplatePinError(RuntimeError):
    """Fail closed. Never fall back to another layout."""


def sha256_file(path: Path) -> str:
    h = hashlib.sha256()
    with path.open("rb") as f:
        for chunk in iter(lambda: f.read(1 << 20), b""):
            h.update(chunk)
    return h.hexdigest()


def verify_pin(pin: dict) -> Presentation:
    # Gate 1 ??byte identity of the renderer template.
    tpl = Path(pin["renderer_template"]["filename"])
    actual = sha256_file(tpl)
    if actual != pin["renderer_template"]["sha256"]:
        raise TemplatePinError(
            f"renderer template SHA mismatch\n  expected {pin['renderer_template']['sha256']}"
            f"\n  actual   {actual}\n"
            "Rebuild via aippt.tools.make_renderer_template and RE-PIN deliberately."
        )

    # Gate 2 ??structural signature. Catches a re-pinned-but-wrong package.
    prs = Presentation(str(tpl))
    sig = pin["layout_signature"]
    checks = [
        (len(prs.slides) == sig["slide_count"], "renderer template must contain 0 slides"),
        (len(prs.slide_layouts) == sig["layout_count"], "layout count changed"),
        (prs.slide_width == sig["slide_width_emu"], "slide width changed"),
        (prs.slide_height == sig["slide_height_emu"], "slide height changed"),
    ]
    layout = prs.slide_layouts[sig["layout_index"]]
    checks += [
        (str(layout.part.partname) == sig["layout_partname"], "layout 3 partname changed"),
        (sorted(p.placeholder_format.idx for p in layout.placeholders) == sig["placeholder_idxs"],
         "layout 3 placeholder idx set changed"),
    ]
    got = {Path(r.target_partname).name for r in layout.part.rels.values() if not r.is_external}
    checks.append((set(sig["required_media"]) <= got,
                   f"layout 3 lost media: {sig['required_media']} vs {sorted(got)}"))

    ph = layout.placeholders[10]
    exp = sig["placeholder_10_emu"]
    checks.append((
        (ph.left, ph.top, ph.width, ph.height) == (exp["left"], exp["top"], exp["width"], exp["height"]),
        "placeholder idx 10 geometry moved",
    ))

    for ok, msg in checks:
        if not ok:
            raise TemplatePinError(f"layout signature mismatch: {msg}")
    return prs
```

The Canvas IR payload also carries `target.template_sha256`. The backend **hard-fails** on mismatch rather than rescaling a stale payload into a subtly-wrong deck.

### 4.3 Re-pinning is a deliberate, reviewed act

Changing the pin is a code change: run the builder, run the audit, run the calibration slide, update `template_pin.json`, commit the new `renderer_template.pptx`. There is no auto-repin, no `--force`, no environment-variable escape hatch.

> **Housekeeping:** `~$Vieworks_R&D_ppt_Template.pptx` in the task directory is an Office lock file. It means the template may be open in PowerPoint. Never hash it, never read it, and close PowerPoint before running the builder.

## 5. Frontend architecture ??HTML/JS

### 5.1 Technology choice: DOM + inline SVG. **Not `<canvas>`. Not Fabric.js.**

Fabric is a `<canvas>` library. Text becomes bitmap-rendered by *Fabric's own* layout engine, which means (a) you reimplement text editing from scratch, and (b) Fabric's wrapping metrics become a **third text engine**, agreeing with neither the browser nor PowerPoint. For a project whose headline risk is text overflow, adding a third metric model is a bad trade.

The DOM gives you, free:
- `contenteditable` ??real text editing, nothing to reimplement;
- **real browser metrics in the real Century Gothic** ??the closest possible preview of what PowerPoint will do;
- the element *is* the model (`el.dataset.x`), so serialization is trivial.

Total library requirement: **interact.js (~10 KB)** for drag/resize handles and snapping ??or ~150 lines of `pointerdown`/`pointermove`/`pointerup` with pointer capture. Nothing else.

### 5.2 Canvas sizing and the coordinate system

**The model space is 960 횞 540 logical units, and nothing else ever enters the IR.**

```
1 logical unit  ?? 1 pt  ?? exactly 12,700 EMU        (12192000/960 = 6858000/540 = 914400/72)
```

Consequences that delete whole bug classes before they exist:
- Geometry: `emu = round(u * 12700)` ??integer, exact.
- **Font size maps 1:1** ??a size-14 run is `Pt(14)`. No scale factor anywhere. (1280횞720 also divides exactly, at 9525 EMU/px, but then every font size needs a 횞0.75 factor. 960횞540 is strictly better.)

**Decouple model space from display.** The stage is a `960 횞 540` div in *logical* units; zoom is a single `transform: scale(s)` with `transform-origin: 0 0`.

```css
#stage {
  position: relative;
  width: 960px; height: 540px;          /* 1 CSS px == 1 logical unit at s = 1 */
  transform: scale(var(--zoom));
  transform-origin: 0 0;
  background: #FFFFFF;
  overflow: hidden;
}
```

**The zoom-inversion rule (critic rule 7), stated once and obeyed everywhere:**

```js
// The ONLY place a device coordinate becomes a model coordinate.
function toModel(ev) {
  const r = stage.getBoundingClientRect();   // used ONLY for pointer inversion
  return { x: (ev.clientX - r.left) / zoom,  // `zoom` is the single source of truth
           y: (ev.clientY - r.top)  / zoom };
}
```

**Forbidden in the IR path, without exception:** `getBoundingClientRect()` widths/heights, `offsetWidth`, `clientWidth`, `devicePixelRatio`, responsive/percentage widths, any value read back from computed CSS. Geometry lives in JS state (`el.dataset.x/y/w/h`), and CSS is written *from* that state, never read back into it. `getBoundingClientRect()` appears exactly once, in `toModel()`.

Round only at the final `logical 횞 12700` conversion ??carry floats in the IR, round in Python.

### 5.3 Element model, z-order, and the red line

```html
<div id="stage">
  <!-- editor-only chrome: CSS pseudo-elements. Structurally cannot be serialized. -->
  <!-- #stage::before = the title box outline; #stage::after = the red divider line -->
  <div class="el" data-type="rect" data-x="100" data-y="120" data-w="180" data-h="60">??/div>
  ??
</div>
```

- **Array order in the DOM IS z-order.** No `z` field. A separate `z` is a second source of truth and will desync.
- **The red line is `#stage::after`** ??a CSS pseudo-element. It has no DOM node, therefore the serializer *cannot* emit it even by accident (critic rule 6). The layout already draws the real gradient divider; if the exporter also emitted the red line, **the deck would ship two stacked dividers**.

```css
#stage::after {                 /* editor-only. Approximates the visible gradient band. */
  content: ""; position: absolute; pointer-events: none;
  left: 46.4px; top: 71px;      /* visible band centre y = 72.0; audited 68.88??5.12 */
  width: 742.3px; height: 2px;  /* audited x 46.41 ??788.68 */
  background: #FF0032;
}
#stage::before {                /* the locked title box, TITLE_LOCKED */
  content: ""; position: absolute; pointer-events: none;
  left: 45.55px; top: 26.75px; width: 725.29px; height: 37.25px;
  outline: 1px dashed rgba(0,0,0,.25);
}
```

**Tell the user plainly:** the editor shows a flat red line; PowerPoint shows the real gradient. **The header region is deliberately not WYSIWYG.** The geometry above is an evidence-based approximation of the gradient's visible centre, not the divider picture's outer box.

**Better, once LibreOffice is available (a Phase 3 dependency, but cheap to pull forward):** render layout 3 to a PNG once and set it as the stage's `background-image`. The editor then shows the *real* logo and the *real* gradient, the red-line-position question evaporates, and the header becomes genuinely WYSIWYG. The flat red line is a perfectly good day-one MVP; the PNG background is the target.

### 5.4 Shapes: inline SVG, because SVG stroke semantics == DrawingML stroke semantics

Critic rule 8 demands we **define whether stroke is included in `w`/`h`**. We define it by construction:

> **`x, y, w, h` are the shape's *unrotated path box*. Stroke is NOT included; it is centred on the path and bleeds `stroke/2` outward on every side.**

That is exactly what DrawingML does (`<a:off>`/`<a:ext>` is the path box; `<a:ln w=??` is centred) **and exactly what SVG does**. Using CSS borders instead would import CSS `box-sizing` semantics (border drawn *inward*), producing a visible `stroke/2` edge drift on every shape ??a bug that presents as a coordinate error and burns a day.

So every shape is an inline `<svg>` with a 1:1 viewBox and `overflow: visible`:

```html
<div class="el" style="left:100px; top:120px; width:180px; height:60px;">
  <svg width="180" height="60" viewBox="0 0 180 60" preserveAspectRatio="none"
       style="overflow: visible; position:absolute; inset:0;">
    <rect x="0" y="0" width="180" height="60"
          fill="#FF0032" stroke="#FFFFFF" stroke-width="1"/>
  </svg>
  <div class="txt" contenteditable="true">Capture</div>
</div>
```

| Editor shape | SVG | `python-pptx` | `prst` |
|---|---|---|---|
| Rectangle | `<rect>` | `MSO_SHAPE.RECTANGLE` | `rect` |
| Circle / ellipse | `<ellipse>` | `MSO_SHAPE.OVAL` | `ellipse` |
| Triangle | `<polygon points="w/2,0 w,h 0,h">` | `MSO_SHAPE.ISOSCELES_TRIANGLE` | `triangle` |
| Connector | `<line>` + `<marker>` | `add_connector(...)` | ??(짠6.7) |

`viewBox` is 1:1 with the element box, so `stroke-width` is in logical units with no scaling distortion. `overflow: visible` lets the outer half of the stroke draw. `preserveAspectRatio="none"` keeps resize honest.

### 5.5 Rotation

**Centre-origin, degrees clockwise, in both systems.** CSS `transform: rotate(Ndeg)` with `transform-origin: 50% 50%` on `.el`; `shape.rotation = N` in python-pptx rotates about the shape centre. Same convention, no conversion. `x/y/w/h` always describe the **unrotated** box.

### 5.6 Text: the CSS contract that must match the renderer

Critic rule 8, plus the "browser text is a preview, not proof" finding. Every one of these has a PowerPoint counterpart in 짠6.6, and they must be changed **together**:

```css
.el .txt {
  position: absolute;
  /* PowerPoint's default text-frame insets: 0.1in L/R, 0.05in T/B = 7.2 / 3.6 logical units.
     Hard-coded on both sides. This is the trap that reads like a coordinate bug. */
  left: 7.2px; right: 7.2px; top: 3.6px; bottom: 3.6px;
  box-sizing: border-box;
  padding: 0; margin: 0; border: 0;

  font-family: 'Century Gothic', 'Malgun Gothic', sans-serif;  /* mirrors latin/ea split */
  font-size: 14px;              /* == 14 pt in the model */
  line-height: 1.2;             /* must equal renderer line_spacing */
  white-space: pre-wrap;        /* word_wrap = True */
  overflow-wrap: break-word;
  word-break: keep-all;         /* Korean: break at spaces, not mid-word */

  display: flex;                /* autoshape default is anchor="ctr" + algn="ctr" */
  align-items: center;          /* valign ctr  -> tf.vertical_anchor = MSO_ANCHOR.MIDDLE */
  justify-content: center;      /* align  ctr  -> p.alignment = PP_ALIGN.CENTER */
  text-align: center;
  overflow: visible;            /* show overflow; do NOT hide the problem */
}
```

**Overflow is shown, never clipped.** If the text does not fit in the browser, the user sees it and fixes it. That is the entire defence, and it is a far stronger one than any character-budget heuristic ??but see 짠7.4: it is a *preview*, not a proof.

**`contenteditable` normalization ??specify before writing the serializer.** The browser emits `<div>`, `<br>`, `&nbsp;`, and styled `<span>`s. The serializer must normalize to an explicit run model:

| DOM | IR |
|---|---|
| block-level `<div>` / `<p>` | new paragraph |
| `<br>` | line break within a paragraph (`<a:br/>`) |
| `&nbsp;` (U+00A0) | preserved as U+00A0 (do **not** collapse to a space) |
| `<b>`/`<strong>`, `<i>`/`<em>`, colour spans | run-level `bold` / `italic` / `color` |
| everything else | flattened to plain text |

Reject C0 control characters except `\t` and `\n` at validation time. **This is an interoperability/validation policy, not a corruption fix** ??`python-pptx` 1.0.x escapes unsupported control characters, so the "illegal chars corrupt the deck" claim in `plan_review.md` 짠2 is overstated. Reject them anyway; they have no legitimate source in a visual editor.

### 5.7 Editor constraints (enforced in the UI, re-enforced in the renderer)

- Elements cannot be dragged or resized into `HEADER_RESERVED` or `FOOTER_RESERVED`, and are clamped to the 960 횞 540 slide.
- The title box is fixed at `TITLE_LOCKED`; it is a *title field*, not an element.
- Non-positive `w`/`h` are impossible (minimum 4 logical units).
- **Font availability check** on load ??warn loudly if the preview is lying:



### 6.2 The render loop ??Layout 3 adoption, not cloning

`renderer_draft_brief.md` specifies an `lxml` slide-cloning engine. **It is not needed for this path and should be dropped from Phase-1 scope.** Cloning exists to *reuse hand-designed slides*. A human drawing from scratch does not want to reuse a design ??they want the *chrome*, and the chrome is inherited from the layout for free.

The Q3 objection that originally blocked `add_slide()` is **lifted for this narrowly defined path** (critic 짠1, explicitly): it was an objection to *reusing designs*, and it remains valid for that. It does not bind here, because we deliberately draw our own body content and inherit only chrome.

```python
def render(ir: dict, pin: dict) -> Presentation:
    prs = verify_pin(pin)                                # 짠4 ??fail closed
    if ir["canvas"] != {"w": 960, "h": 540, "unit": "pt"}:
        raise ValueError("stale payload: canvas dims do not match the model space")
    if ir["target"]["template_sha256"] != pin["renderer_template"]["sha256"]:
        raise ValueError("stale payload: template SHA mismatch")

    layout = prs.slide_layouts[pin["layout_signature"]["layout_index"]]   # 3
    slide = prs.slides.add_slide(layout)   # logo + divider + page number, inherited, free

    set_title(slide, ir["title"])                        # 짠6.3
    for el in ir["elements"]:                            # array order IS z-order
        draw(slide, el)                                  # 짠6.4
    return prs
```

`add_slide()` clones the layout's eligible placeholders ??BODY placeholders are cloneable; only date, footer and slide-number placeholders are excluded. So **idx 10 arrives on the slide**, while the logo and divider stay layout-level (and therefore invisible to `slide.shapes` ??hence 짠3.2's protected regions; a collision check that inspects only `slide.shapes` will not see the chrome).

### 6.3 The title ??placeholder idx 10, by idx, never by position

```python
def set_title(slide, text: str) -> None:
```

### 6.4 Shapes ??overcoming the default Office blue

`new_autoshape_sp` hard-codes a `<p:style>` block pointing `lnRef`, `fillRef` and `effectRef` at `schemeClr accent1`, and `fontRef` at `lt1`. **`accent1` in this template is `#4472C4`** ??stock Office blue (`layout_manifest.json:42`). So **every shape arrives blue-filled, blue-outlined, drop-shadowed, with white theme-font text.**

Four overrides. The third is the one everyone forgets:

```python
def draw_shape(slide, el) -> None:
    shp = slide.shapes.add_shape(
        PRST[el["type"]],                               # RECTANGLE / OVAL / ISOSCELES_TRIANGLE
        Emu(round(el["x"] * 12700)), Emu(round(el["y"] * 12700)),
        Emu(round(el["w"] * 12700)), Emu(round(el["h"] * 12700)),
    )
    shp.rotation = el.get("rotation", 0)                # degrees CW, about centre

    # 1. fill ??kills fillRef -> accent1
    shp.fill.solid()
    shp.fill.fore_color.rgb = RGBColor.from_string(el["fill"].lstrip("#"))

    # 2. line ??kills lnRef -> accent1
    stroke = el.get("stroke")
    if stroke:
        shp.line.color.rgb = RGBColor.from_string(stroke["color"].lstrip("#"))
        shp.line.width = Pt(stroke["width"])
    else:
        shp.line.fill.background()                      # explicit "no line", not inherited

    # 3. THE ONE EVERYONE FORGETS ??kills effectRef -> the Office drop shadow.
    #    No amount of fill/line overriding removes it. There is no other shadow API.
    shp.shadow.inherit = False

    # 4. text ??kills fontRef -> lt1 (white) + theme font
    style_text_frame(shp.text_frame, el.get("text"))
```

**Invariant: `#4472C4` must never appear in a generated shape.** Assert it in the QA harness (짠7.3) ??scan the exported `slide1.xml` for `accent1` and for `4472C4`; both must be absent from the `<p:sp>` elements the renderer created.

Colour policy: **new content defaults to `#FF0032`** (the user's authoritative override); **inherited template chrome keeps its native branding** and is never recoloured. Use opaque `#RRGGBB` in Phase 1 ??transparency semantics are out of scope until separately specified.

### 6.5 Fonts ??the Latin/EA split (mandatory)

**"Century Gothic for both English and Korean" is not achievable.** Century Gothic ships no Hangul glyphs; no API can conjure them. And `python-pptx` cannot even express an East-Asian typeface: `Font.name` writes **only** `<a:latin>`, and `CT_TextCharacterProperties` declares no `<a:ea>` element at all. You must drop to lxml.

The honest contract is a **split**:

```
latin = "Century Gothic"        ea = "留묒? 怨좊뵓" (Malgun Gothic)
CSS:  font-family: 'Century Gothic', 'Malgun Gothic', sans-serif;
```

This is the pleasing part: **the browser's font-fallback chain and PowerPoint's latin/ea split are the same mechanism.** Configure them consistently and preview and export agree ??that is the only route to WYSIWYG for mixed KO/EN. Chase "Century Gothic for Korean" and they diverge forever.

```python
from pptx.oxml.ns import qn

LATIN = "Century Gothic"
EA = "留묒? 怨좊뵓"           # installed Hangul fallback; must exist in BOTH browser and export env

def set_run_fonts(run, latin: str = LATIN, ea: str = EA) -> None:
    rPr = run._r.get_or_add_rPr()
    rPr.get_or_add_latin().typeface = latin
    ea_el = rPr.find(qn("a:ea"))
    if ea_el is None:
        ea_el = rPr.makeelement(qn("a:ea"), {})
        # a:ea must follow a:latin and precede a:cs/a:sym/a:hlink... per the DrawingML schema.
        rPr.insert_element_before(
            ea_el, "a:cs", "a:sym", "a:hlinkClick", "a:hlinkMouseOver", "a:rtl", "a:extLst"
        )
    ea_el.set("typeface", ea)
```

**Two font facts the user must decide on before Phase 1 closes** (see D-1, 짠10):

- **Century Gothic is not the Vieworks brand font.** `exemplar_catalog.md` shows the template's real design fonts are **酉곗썚??B** and **酉곗썚??M**, set at run level on every slide. Century Gothic body text will sit next to inherited 酉곗썚??chrome and look subtly off-brand. That may be fine ??but it should be a decision, not an accident.
- **If Century Gothic is not installed on the opening machine, PowerPoint substitutes and geometry shifts.** `python-pptx` cannot embed fonts. Low probability, invisible until someone else opens the deck. Detect-and-warn in the browser (짠5.7) and in the export environment.

### 6.6 Text frames ??the margin trap, and the truth about autofit

**The trap nobody writes down: text-frame internal margins.** PowerPoint defaults to 0.1 in left/right and 0.05 in top/bottom (91,440 / 45,720 EMU) ??**7.2 and 3.6 logical units**. If the HTML div uses `padding: 0`, the browser wraps text at a *different width* than PowerPoint does, and you get an off-by-one-line overflow that presents as a coordinate bug. Set both sides explicitly and identically (this mirrors 짠5.6 exactly):

```python
def style_text_frame(tf, text: dict | None) -> None:
    tf.margin_left = tf.margin_right = Pt(7.2)     # == CSS left/right: 7.2px
    tf.margin_top = tf.margin_bottom = Pt(3.6)     # == CSS top/bottom: 3.6px
    tf.word_wrap = True                            # == white-space: pre-wrap
    tf.auto_size = MSO_AUTO_SIZE.NONE
    tf.vertical_anchor = MSO_ANCHOR.MIDDLE         # == align-items: center

    if not text:
        return
    tf.clear()
    for i, para in enumerate(text["paragraphs"]):
        p = tf.paragraphs[0] if i == 0 else tf.add_paragraph()
        p.alignment = PP_ALIGN[text.get("align", "CENTER")]
        p.space_before = Pt(0)                     # explicit ??do not inherit
        p.space_after = Pt(0)
        p.line_spacing = 1.2                       # == CSS line-height: 1.2
        for r in para["runs"]:
            run = p.add_run()
            run.text = r["t"]
            run.font.size = Pt(r["size"])          # 1:1 with the model. No factor.
            run.font.bold = r.get("bold", False)
            run.font.italic = r.get("italic", False)
            run.font.color.rgb = RGBColor.from_string(r["color"].lstrip("#"))
            set_run_fonts(run)                     # latin + ea
```

**On autofit, state it precisely:** there is **no guaranteed headless PowerPoint-equivalent autofit**. `TextFrame.fit_text()` *does* exist ??`plan_review.md`'s "there is no autofit" is too absolute ??but it needs a TTF path, it is not a PowerPoint rendering engine, and it is a poor foundation for mixed-font CJK fidelity. **Do not build on it.** Set `auto_size = NONE`, let the human size the box, and keep **deterministic render QA as the authority** (짠7).

### 6.7 Connectors and arrowheads ??**in scope for Phase 1**

Critic rule 10: *add a connector schema/tool, or explicitly declare arrows out of scope.* The brief's shape list (rectangle, circle, triangle) contains **no connector or arrow tool at all** ??and "flow charts or block diagrams" with nodes but no arrows is not a flow chart. **Decide it now, in the Phase-1 schema, not after the toolbar is built.**

**Decision: connectors ship in Phase 1, with explicit absolute endpoints and no gluing.**

```python
def draw_connector(slide, el) -> None:
    # Endpoints in logical units. Connectors are emitted BEFORE nodes (array order = z-order),
    # so lines sit behind boxes ??the editor forces new connectors to the back of the array.
    cxn = slide.shapes.add_connector(
        MSO_CONNECTOR.STRAIGHT if el["kind"] == "straight" else MSO_CONNECTOR.ELBOW,
        Emu(round(el["x1"] * 12700)), Emu(round(el["y1"] * 12700)),
        Emu(round(el["x2"] * 12700)), Emu(round(el["y2"] * 12700)),
    )
    cxn.line.color.rgb = RGBColor.from_string(el["color"].lstrip("#"))
    cxn.line.width = Pt(el["width"])
    cxn.shadow.inherit = False                     # connectors get the Office shadow too

    # Arrowheads are NOT exposed in the python-pptx API. There is no line.end_arrow.
    ln = cxn.line._get_or_add_ln()
    if el["arrow"] in ("end", "both"):
        ln.append(ln.makeelement(qn("a:tailEnd"), {"type": "triangle"}))
    if el["arrow"] in ("start", "both"):
        ln.append(ln.makeelement(qn("a:headEnd"), {"type": "triangle"}))
```

**`begin_connect()` / `end_connect()` are explicitly NOT used in Phase 1.** They are experimental, and connection-site indices are unreliable for arbitrary shapes (notably triangles). Gluing is genuinely valuable ??a glued connector stays attached when the user later drags a box *in PowerPoint* ??so revisit it in Phase 2, behind a fixture suite. Phase 1 ships absolute endpoints, which always work.

**Every connector fixture must be saved, reopened, and rendered** (짠7.3).

### 7.4 Say the quiet part out loud: the browser is a preview, not a proof

The visual editor **reduces** text-overflow risk enormously ??a human sizes the box and sees the text in it, which is a far stronger defence than any character-budget heuristic. ### 7.5 Acceptance: tolerances and rendered evidence ??not coordinate equality

Critic rule 12. Coordinate equality proves the *transform*, not the *render*. Acceptance requires:

- **Geometry:** 0 EMU drift on round-trip read-back (짠7.3) ??exact.
- **Raster:** shape edges within **??2 px** of the HTML stage screenshot at 960횞540, from a render by the **actual target consumer**.
- **Text:** the same **number of lines** and no overflow beyond the box, **in the rendered output** ??not in the browser.
- Logo and divider visibly correct and undistorted.

Do not write "WYSIWYG" in any user-facing doc without pointing at that evidence.

## 8. The scoping consequence (say it out loud)

**There are now two IRs, and that is correct ??but it is not free.**

| | Semantic IR (existing) | Canvas IR (this plan) |
|---|---|---|
| Emits | `layout_id` + content blocks | absolute geometry |
| Author | the **AI** | a **human** |
| Invariant | *"the AI never emits coordinates"* | the human emits nothing but coordinates |

These are philosophically opposite, and the README's core invariant explicitly forbids the second ??**for the AI**. That invariant is still right and still holds: a human emitting geometry in a visual editor is not the failure mode it was written to prevent (an LLM hallucinating layout). **Keep both. Do not merge them.** They converge only at the low-level "draw a shape on a slide" primitives.

But the cost must be stated plainly: **this plan makes `html_adapter.py` and the 30-slide HTML corpus dead code for the visual-editor path.** Phase 1 as previously defined (HTML corpus ??IR ??PPTX round-trip, no AI) is not *extended* by this plan ??it is **replaced**. The visual editor may well be the better product; but this is a scope decision with sunk cost, not a free addition.

```jsonc
    },

      "fill": "#FF0032",                                // opaque #RRGGBB. NEVER #4472C4.
      "stroke": { "color": "#FFFFFF", "width": 1 },     // centred on the path (SVG == DrawingML)
      "text": {

        "paragraphs": [
          { "runs": [ { "t": "Capture", "size": 14, "bold": true, "italic": false, "color": "#FFFFFF" } ] }
        ]
      }
    }
  ]
}
```

**Rules baked into the schema:**

- **Version it.** This IR *will* change. `schema` is required and checked.
- **Echo the canvas dims and the template SHA** so the backend rejects a stale payload rather than silently rescaling it into a subtly-wrong deck.
- **Array order is z-order.** A separate `z` field is a second source of truth and will desync.
- **The title is a field, not an element.** It maps to inherited placeholder idx 10 ??on-brand and correctly positioned for free.
- **No editor chrome is representable.** There is no element type for the red line or the title outline; they are CSS pseudo-elements with no DOM node.
- **`w`, `h` > 0**; all geometry clamped to 960 횞 540 and rejected if it intersects a reserved region.
- **Colours are opaque `#RRGGBB`.** `#FF0032` is the default for new content.

    4: 
    5:     python src/aippt/tools/make_renderer_template.py --write-pin
    6: 
    7: Run once, commit the output, pin its SHA in reference/template_pin.json. NEVER import this from
    8: the request path: it is the ONLY sanctioned use of python-pptx's private slide-deletion surface
    9: (critic rule 3). The source template is opened read-only and never written back -- the save
   10: target is asserted to be a different path before anything is saved.
   11: 
   12: Why a separate artifact exists at all: Presentation(SRC) opens a deck that ALREADY HAS 23
   13: exemplar slides, and the public Slides API has no delete operation. add_slide() would append a
   14: 24th, every export would ship the other 23, and the inherited page-number field on the new slide
   15: would read 24.
   16: 
   17: Why the pin is written from the observed package and never from a literal typed in by hand: a
   18: hand-copied signature pins what someone believed, and the whole point of the pin is to catch the
   19: day that belief stops being true. Everything under "layout_signature" below is read back off the
   20: package this script just built.

   75: def sha256_file(path: Path) -> str:
   76:     h = hashlib.sha256()
   77:     with path.open("rb") as f:
   78:         for chunk in iter(lambda: f.read(1 << 20), b""):
   79:             h.update(chunk)
   80:     return h.hexdigest()

   83: def delete_all_slides(prs: Presentation) -> int:
   84:     """Remove every slide from an open Presentation. Returns the count removed.
   85: 
   86:     THE LANDMINE. `Presentation.slides` is not a plain accessor. Every evaluation of it runs
   87: 
   88:         self.part.rename_slide_parts([sldId.rId for sldId in sldIdLst])
   89: 
   90:     which does a `related_part(rId)` lookup for every <p:sldId> still in the list. Evaluate
   91:     `prs.slides` at any moment when a relationship has been dropped but its <p:sldId> is still
   92:     present and that lookup raises KeyError on a package that is only transiently inconsistent.
   93:     (In python-pptx 1.0.2 `slides` happens to be a @lazyproperty, so the cache hides this today.
   94:     That is an implementation detail of one version, not a contract, and it is not what this code
   95:     relies on.)
   96: 
   97:     So: bind the XML element ONCE, mutate only the element, and do not read `prs.slides` again
   98:     until the loop has finished and the package is consistent.
   99: 
  100:     Why drop_rel AND the sldId removal, rather than just the sldId: python-pptx serializes every
  101:     part reachable through the relationship graph. Removing only the <p:sldId> entry leaves the
  102:     presentation.xml.rels relationship intact, so all 23 slide parts would still be written into
  103:     the package -- invisible in PowerPoint, but dead weight and a source of confusing audits.
  104:     """
  105:     sld_id_lst = prs.slides._sldIdLst  # bind once; see docstring
  106:     removed = 0
  107:     for sld_id in list(sld_id_lst):  # list(): never mutate the tree you are iterating
  108:         # drop_rel first, while the <p:sldId> still carries the r:id. XmlPart.drop_rel pops the
  109:         # rel only when its reference count is < 2, and right now it is exactly 1.
  110:         prs.part.drop_rel(sld_id.rId)
  111:         sld_id_lst.remove(sld_id)
  112:         removed += 1
  113:     return removed

  144: def observe_signature(prs: Presentation) -> dict[str, Any]:
  145:     """Read the layout signature back off the package. This -- not a hand-typed literal -- is

  178: def check_signature(sig: dict[str, Any]) -> None:

  198: def audit_package(path: Path) -> None:
  199:     """Acceptance gate (plan Sec 2.3), checks 1-4, run against the saved ZIP.
  200: 
  201:     Checks 1-3 are re-read through python-pptx by the caller; this function is the part that has
  202:     to look at the raw package, because "no orphaned parts" and "no dangling relationships" are
  203:     properties of the ZIP, not of the object model.
  204:     """
  205:     problems: list[str] = []
  206:     with zipfile.ZipFile(path) as zf:
  207:         names = set(zf.namelist())
  208: 
  209:         strays = sorted(n for n in names if n.startswith(("ppt/slides/", "ppt/notesSlides/")))
  210:         if strays:
  211:             problems.append(f"slide/notes parts survived into the package: {strays}")
  212: 
  213:         for media in EXPECT_MEDIA:
  214:             if f"ppt/media/{media}" not in names:
  215:                 problems.append(f"ppt/media/{media} is missing from the package")
  216: 
  217:         # Dangling relationships: every internal Target must resolve to a part that exists.
  218:         for rels_name in sorted(n for n in names if n.endswith(".rels")):
  219:             part_dir = posixpath.dirname(posixpath.dirname(rels_name))  # ppt/_rels/x.rels -> ppt
  220:             for rel in etree.fromstring(zf.read(rels_name)):
  221:                 if rel.get("TargetMode") == "External":
  222:                     continue
  223:                 target = rel.get("Target") or ""
  224:                 resolved = (
  225:                     target.lstrip("/")
  226:                     if target.startswith("/")
  227:                     else posixpath.normpath(posixpath.join(part_dir, target))
  228:                 )
  229:                 if resolved not in names:
  230:                     problems.append(f"{rels_name}: dangling rel -> {target}")
  231: 
  232:     if problems:
  233:         raise BuildError("package audit failed:\n  - " + "\n  - ".join(problems))

  236: def has_slide_ph(slide: Any, idx: int) -> bool:
  237:     """True if the slide carries a placeholder with this idx.
  238: 
  239:     The two placeholder collections are exact opposites and there is no way to write this once:
  240:       - slide.placeholders[idx]  -> keyed by IDX, raises KeyError, and has NO .get()
  241:       - layout.placeholders[idx] -> keyed by POSITION (from _BaseShapes), and .get(idx) is the
  242:                                     only idx lookup it offers
  243:     Mixing them up gives you an IndexError from a line that reads like it works.
  244:     """
  245:     try:
  246:         slide.placeholders[idx]
  247:     except KeyError:
  248:         return False
  249:     return True

  252: def smoke_add_slide(path: Path) -> None:
  253:     """Acceptance gate check 6: add_slide(layout 3) -> save -> reopen -> it is slide 1.
  254: 
  255:     The page-number FIELD is rendered by PowerPoint, not by python-pptx, so we cannot assert the
  256:     glyph "1" here -- what we can assert is the only thing that determines it: the new slide is
  257:     the one and only slide, at index 0. Reading the rendered "1" is a human check
  258:     (HUMAN_VERIFICATION.md).
  259:     """
  260:     prs = Presentation(str(path))
  261:     slide = prs.slides.add_slide(prs.slide_layouts[LAYOUT_INDEX])
  262:     if not has_slide_ph(slide, TITLE_PH_IDX):
  263:         raise BuildError(f"add_slide did not clone placeholder idx {TITLE_PH_IDX} onto the slide")
  264: 
  265:     with tempfile.TemporaryDirectory() as tmp:
  266:         probe = Path(tmp) / "smoke.pptx"
  267:         prs.save(str(probe))
  268:         out = Presentation(str(probe))
  269:         problems: list[str] = []
  270:         if len(out.slides) != 1:
  271:             problems.append(f"expected exactly 1 slide, got {len(out.slides)}")
  272:         else:

  274:             if str(s.slide_layout.part.partname) != EXPECT_LAYOUT_PARTNAME:
  275:                 problems.append(f"slide 1 relates to {s.slide_layout.part.partname}")
  276:             if not has_slide_ph(s, TITLE_PH_IDX):
  277:                 problems.append(f"placeholder idx {TITLE_PH_IDX} did not survive the round trip")

  279:             raise BuildError("smoke test failed:\n  - " + "\n  - ".join(problems))

  282: def build() -> dict[str, Any]:
  283:     if DST.resolve() == SRC.resolve():
  284:         raise BuildError("destination is the source template; refusing to overwrite it")
  285: 
  286:     if not SRC.is_file():
  287:         raise BuildError(f"source template not found: {SRC}")
  288: 
  289:     lock = SRC.with_name("~$" + SRC.name)
  290:     if lock.exists():
  291:         # An Office lock file. Never hashed, never read -- but its presence means the template is
  292:         # probably open in PowerPoint, which is worth saying out loud before we read it.
  293:         print(f"warning: {lock.name} exists -- close PowerPoint before trusting this build.",
  294:               file=sys.stderr)
  295: 
  296:     src_sha = sha256_file(SRC)
  297:     if src_sha != SRC_SHA:
  298:         raise BuildError(
  299:             f"source template changed\n  expected {SRC_SHA}\n  actual   {src_sha}\n"
  300:             "This builder was written against the expected package. Re-audit the template "
  301:             "(aippt.analyze_pptx_master), update SRC_SHA deliberately, then rebuild."
  302:         )
  303: 
  304:     prs = Presentation(str(SRC))  # SRC is opened read-only and never saved back
  305:     removed = delete_all_slides(prs)
  306: 
  307:     DST.parent.mkdir(parents=True, exist_ok=True)
  308:     prs.save(str(DST))
  309: 
  310:     out = Presentation(str(DST))  # re-read: audit the artifact, not the in-memory object
  311:     sig = observe_signature(out)
  312:     check_signature(sig)
  313:     audit_package(DST)
  314:     smoke_add_slide(DST)
  315: 
  316:     return {
  317:         "slides_removed": removed,
  318:         "source_template": {
  319:             "filename": SRC.name,
  320:             "sha256": src_sha,
  321:             "bytes": SRC.stat().st_size,
  322:         },
  323:         "renderer_template": {
  324:             "filename": DST.relative_to(PROJECT_ROOT).as_posix(),
  325:             "sha256": sha256_file(DST),
  326:             "bytes": DST.stat().st_size,
  327:             "built_from_sha256": src_sha,
  328:             "builder": BUILDER,
  329:         },
  330:         "layout_signature": sig,
  331:         "theme": {
  332:             "accent1": _accent1(out),
  333:             "note": "Office blue. MUST NOT appear in any generated shape.",
  334:         },
  335:     }

===== src\aippt\canvas\pin.py =====
    1: #!/usr/bin/env python3
    2: # -*- coding: utf-8 -*-
    3: """Template pinning. Two gates, both mandatory, both at PROCESS START -- not per request.
    4: 
    5: Hard-coding `slide_layouts[3]` is safe ONLY while the package is pinned (critic rule 4). A
    6: template that is changed, re-cut or re-ordered must fail closed with a clear error. It must never
    7: silently select a different layout, because a "successful" export onto the wrong layout is a
    8: worse outcome than a crash: it looks fine, ships, and is discovered by the audience.
    9: 
   10:     pin = load_pin()
   11:     verify_pin(pin)                      # raises TemplatePinError, or returns
   12:     prs = open_renderer_template(pin)    # verified again; cheap next to being wrong
   13: 
   14: Gate 1 is byte identity of the renderer template. Gate 2 is its structural signature, and it
   15: exists because gate 1 alone can be defeated by the one mistake we actually expect: someone
   16: rebuilds the template, sees the SHA mismatch, pastes the new SHA into template_pin.json to make
   17: the error go away, and never notices that layout 3 is now a different layout.
   18: 
   19: There is no auto-repin, no --force, and no environment-variable escape hatch. Re-pinning means
   20: running the builder, reading its output, and committing the new artifact deliberately (Sec 4.3).
   21: 
   22: This module never reads the SOURCE template: it is a build-time input, not a runtime one, and the
   23: request path must not depend on a 1.8 MB deck it does not use.
   24: """
   25: 
   26: from __future__ import annotations
   27: 
   28: import hashlib
   29: import json
   30: import posixpath
   31: from pathlib import Path
   32: from typing import Any
   33: 
   34: from pptx import Presentation
   35: 
   36: # <root>/src/aippt/canvas/pin.py -> <root>. The pin file names paths relative to the project
   37: # root, so they must be resolved against it and not against the caller's cwd.
   38: PROJECT_ROOT = Path(__file__).resolve().parents[3]
   39: PIN_PATH = PROJECT_ROOT / "reference" / "template_pin.json"
   40: 
   41: PIN_VERSION = 1
   42: TITLE_PH_IDX = 10
   43: 
   44: # What make_renderer_template.py has not yet filled in. A freshly-checked-out pin carries this
   45: # and MUST fail: an unpinned template is an unverified template.
   46: UNPINNED = "<FILL FROM make_renderer_template.py OUTPUT>"
   47: 
   48: _REBUILD = (
   49:     "Rebuild via `python src/aippt/tools/make_renderer_template.py --write-pin` "
   50:     "and RE-PIN deliberately."
   51: )
   52: 
   53: 
   54: class TemplatePinError(RuntimeError):
   55:     """Fail closed. Never fall back to another layout."""
   56: 
   57: 
   58: def sha256_file(path: Path) -> str:
   59:     h = hashlib.sha256()
   60:     with path.open("rb") as f:
   61:         for chunk in iter(lambda: f.read(1 << 20), b""):
   62:             h.update(chunk)
   63:     return h.hexdigest()

   66: def load_pin(path: Path = PIN_PATH) -> dict[str, Any]:
   67:     """Read and structurally validate template_pin.json itself.
   68: 
   69:     This only checks that the pin is a well-formed pin. It says nothing about whether the package
   70:     on disk matches it -- that is verify_pin's job, and keeping them apart is what lets a caller
   71:     report "your pin file is malformed" separately from "your template has drifted".
   72:     """
   73:     try:
   74:         pin = json.loads(path.read_text(encoding="utf-8"))
   75:     except FileNotFoundError:
   76:         raise TemplatePinError(f"pin file not found: {path}\n{_REBUILD}") from None
   77:     except json.JSONDecodeError as exc:

  316: def roundtrip(dst: Path, expected: dict[str, dict[str, int]]) -> list[str]:
  317:     """Re-open the export and assert 0 EMU drift (plan Sec 7.3). This is the machine-checkable
  318:     half of calibration; the raster diff is the other half and it needs a human or a renderer.
  319: 
  320:     Tolerance is 0, not "small": emu = round(u * 12700) is exact, so any drift at all means the
  321:     write path changed the number, and a write path that rounds is a write path that will keep
  322:     rounding.
  323:     """
  324:     out = Presentation(str(dst))
  325:     problems: list[str] = []
  326: 
  327:     if len(out.slides) != 1:
  328:         problems.append(f"expected exactly 1 slide, got {len(out.slides)}")
  329:         return problems
  330:     slide = out.slides[0]
  331: 
  332:     by_name = {sh.name: sh for sh in slide.shapes}

  316: def roundtrip(dst: Path, expected: dict[str, dict[str, int]]) -> list[str]:
  317:     """Re-open the export and assert 0 EMU drift (plan Sec 7.3). This is the machine-checkable
  318:     half of calibration; the raster diff is the other half and it needs a human or a renderer.
  319: 
  320:     Tolerance is 0, not "small": emu = round(u * 12700) is exact, so any drift at all means the
  321:     write path changed the number, and a write path that rounds is a write path that will keep
  322:     rounding.
  323:     """
  324:     out = Presentation(str(dst))
  325:     problems: list[str] = []
  326: 
  327:     if len(out.slides) != 1:
  328:         problems.append(f"expected exactly 1 slide, got {len(out.slides)}")
  329:         return problems
  330:     slide = out.slides[0]
  331: 
  332:     by_name = {sh.name: sh for sh in slide.shapes}
  333:     for name, exp in expected.items():
  334:         shp = by_name.get(name)
  335:         if shp is None:
  336:             problems.append(f"{name}: shape missing from the export")
  337:             continue
  338:         got = {
  339:             "left": int(shp.left),
  340:             "top": int(shp.top),
  341:             "width": int(shp.width),
  342:             "height": int(shp.height),
  343:             "rotation": round(float(shp.rotation)),
  344:         }
  345:         for key, want in exp.items():
  346:             if got[key] != want:
  347:                 problems.append(f"{name}.{key}: expected {want}, got {got[key]}")
  348: 
  349:         # The invariant, scoped to the shapes the RENDERER created -- not the whole slide. The
  350:         # inherited placeholder is chrome; it is allowed to reference whatever the template says.
  351:         xml = shp._element.xml
  352:         if "accent1" in xml or FORBIDDEN in xml.upper():
  353:             problems.append(
  354:                 f"{name}: accent1/{FORBIDDEN} present in the shape XML -- an add_shape override "
  355:                 "was missed (fill, line, shadow, text, or the <p:style> strip)"
  356:             )
  357:     return problems
