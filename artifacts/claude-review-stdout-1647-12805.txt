### 3. One legality rule, one door

`illegalReason(s)` is **the judge** — it reads state and transforms nothing. `applyConstraints(s, opt)`
is **the transform** (min-extent → snap → clamp) and then calls the judge. `loadIR()` calls the judge
directly and never the transform, so importing a file cannot silently re-snap the user's deck.

`test_there_is_exactly_ONE_copy_of_the_legality_rule` asserts that `applyConstraints()` contains
`illegalReason(` and does **not** contain `REJECT_REGIONS`. Undo/redo does not get its own copy of the
rule either (see §4.2 of "What to build").

`HEADER_RESERVED = [0, 0, 960, 92]` and `FOOTER_RESERVED = [733.6, 500, 960, 540]`, tested against the
**rotated AABB**, half-open (edge contact is not intersection). Ported verbatim from `geometry.py`.
Nothing you add may weaken that.

**Property edits cannot violate the reserved regions, and that is by design, not by luck.** The stroke
is centred on the path box and bleeds `width/2` *outside* `x/y/w/h`, and that bleed is deliberately
**not** part of the reserved-region check (see the `stroke` description in `schema.json` and the caveat
in `geometry.py`). So a stroke-width edit next to the header is legal on both sides.
**Do not "improve" `elementBBox()` to include the stroke.** It would desync the editor from
`geometry.py`, and the user would get a stage that looks legal and a 422 they cannot explain.

### 4 — `editor.js`: Undo / Redo (the actual new work)

#### 4.1 The snapshot is the whole document, and it is built from state — never from the DOM's geometry

```js
// Everything the stage is, as plain data. Read from dataset via read() -- the same one-way flow
// everything else uses. NOTHING here measures anything.
function snapshot() {
  var els = [].slice.call(stage.querySelectorAll(':scope > .el')).map(function (el) {
    var s = read(el);                                   // dataset -> state
    var body = el.querySelector('.txt .body');
    s.html = body ? body.innerHTML : null;              // the runs, verbatim
    return s;
  });
  return {
    title: titleField.innerHTML,
    els: els,                                           // ARRAY ORDER IS Z-ORDER. Preserve it.
    selectedId: selected ? selected.dataset.id : null,
  };
}
```

Why the whole document and not a per-element diff: z-order (`Raise`/`Lower`), delete, duplicate and
Load-JSON are all *document* operations. A per-element undo cannot express them, and a mixed scheme
would need a second source of truth about what changed — which is the bug this codebase spends most of
its comments avoiding. The stage is small; snapshots are cheap.

#### 4.2 Restore rebuilds the stage, and **re-judges** on the way in

```js
function restore(snap) {
  // Every state in a snapshot was legal when it was captured -- it got there through commit() or
  // through loadIR()'s judge. Re-judging is therefore expected to be a no-op, and it costs
  // microseconds. Do it anyway: it keeps "illegalReason() is the ONLY door into the stage" a true
  // sentence rather than a sentence with an exception in it.
  for (var i = 0; i < snap.els.length; i++) {
    if (illegalReason(snap.els[i])) { /* refuse the WHOLE restore; warn(); return; */ }
  }
  // ... clear :scope > .el, select(null), titleField.innerHTML = snap.title,
  //     makeEl(state) + stage.appendChild(el) in array order, body.innerHTML = s.html,
  //     re-select by id, syncProps()
}
```

- Restore calls **the judge, never the transform**. `applyConstraints()` would re-snap and re-clamp a
  state the user already committed — an undo that silently moves things by 3 units is worse than no
  undo. This is exactly the split `loadIR()` exists to demonstrate; copy its posture.
- `stage.appendChild()` in array order preserves z-order exactly. Do not sort.
- **`idSeq` is not rewound.** `nextId()` already loops until the id is unused in the DOM
  (editor.js:472–476), so a restored `el3` cannot collide with a future one. Rewinding the counter would
  *be* the collision.
- `makeEl()` calls `write()` + `renderEl()` + `wire()`, so restored elements come back fully live. There
  is no separate re-wiring step and you must not add one.

#### 4.3 What goes on the stack, and when

Two arrays and a cap:

```js
var past = [], future = [];
var MAX_HISTORY = 100;          // keep every new constant clear of 1920/1080/1280/720/1440/810
```

A snapshot is taken **before** a mutation and pushed **only if the mutation actually changed
something**. That "only if" is not polish — without it, every plain click on an element pushes a no-op
frame (because `Interactions.pointerDrag` fires `start` on `pointerdown`, movement or not), and the
user's first `Ctrl+Z` does nothing at all.

The shape to use, and to reuse everywhere:

```js
var pending = null;
function beginHistory() { if (!pending) pending = JSON.stringify(snapshot()); }
function endHistory() {
  if (!pending) return;
  var before = pending; pending = null;
  if (before === JSON.stringify(snapshot())) return;   // nothing changed -- not a history frame
  past.push(JSON.parse(before));
  if (past.length > MAX_HISTORY) past.shift();
  future.length = 0;                                   // a new action forks the timeline
}
function act(fn) { beginHistory(); fn(); endHistory(); }   // for atomic, one-shot mutations
```

| Mutation | `beginHistory()` | `endHistory()` |
|---|---|---|
| Drag an element / a connector | the `start` callback of `Interactions.draggable` | the **`end`** callback — `draggable()` already forwards `opts.end`, so `interactions.js` needs no change (and it is **out of scope**) |
| Resize (8 handles) | `resizable(...).start` | `resizable(...).end` |
| Rotate; drag a connector endpoint | `pointerDrag(...).start` | `pointerDrag(...).end` |
| Draw a new element (stage drag-out) | the stage `pointerDrag`'s `start` (pre-state = no element) | its `end` |
| Delete, Duplicate, Raise, Lower | wrap the existing handler in `act(...)` | — |
| Colour / number / range inputs (`p-fill`, `p-stroke`, `p-stroke-w`, `p-size`, `p-rot`) | on the **first `input`** of the burst (the `pending` guard makes this automatic) | on the control's **`change`** event, which fires once when the drag or the typing settles — one history frame per gesture, not one per pixel of the colour wheel |
| `<select>` (`p-align`, `p-valign`, `p-kind`, `p-arrow`), bold, italic | `act(...)` around the handler | — |
| Text editing | the `dblclick` handler, **before** focus | `stopEditing()` — the html comparison inside `endHistory()` is what stops a no-op edit becoming a frame |
| Title editing | `titleField` `focus` | `titleField` `blur` |
| **Load JSON** | in the `#f-load` change handler, **before** `loadIR(ir)` | after it returns — and a refused import changed nothing, so `endHistory()`'s comparison drops it by itself. **Do not put either call inside `loadIR()`** (see the Node-harness rule above). |

#### 4.4 The keyboard

Extend the **existing** `keydown` handler (editor.js:1075), which already opens with
`if (editingText(ev.target)) return;`:

- `Ctrl+Z` / `Cmd+Z` → undo. `Ctrl+Y` / `Ctrl+Shift+Z` / `Cmd+Shift+Z` → redo. `preventDefault()` on all
  of them.
- **Keep the `editingText()` early return exactly as it is.** Inside a `contenteditable` or an
  `<input>`, `Ctrl+Z` must reach the *browser's* field-level undo — that is what a user typing into a box
  expects, and fighting it produces an editor where you cannot un-type a letter without losing a shape.
  Our stack takes over the moment the caret leaves, because the text edit lands as one history frame on
  exit (§4.3).
- Undo: `if (!past.length) return; future.push(snapshot()); restore(past.pop());` Redo is the mirror.
  Cap `future` the same way. Set the status line (`setStatus`) so the user can see it happened, and
  disable `b-undo` / `b-redo` if you added them.
- `Delete` / `Backspace` and `Ctrl+D` keep working; they now go through `act(...)`.

## Decisions I am making for you (and why)

| # | Decision | Why |
|---|---|---|
| 1 | The panel is a **fixed right rail**, not a popover anchored to the element | Anchoring needs a measured element rect. That is the Prime Directive, and Gate 1 fails the build |
| 2 | **Move** the existing controls; do not build new ones | The ids are already wired to `patchSelected()` / `syncProps()`. Duplicating them gives you two nodes with one id and a control that silently goes dead |
| 3 | Undo is a **whole-document snapshot**, not a per-element diff | Delete, duplicate, raise/lower and import are document operations. A diff scheme needs a second source of truth about what changed |
| 4 | `restore()` calls **`illegalReason()`, never `applyConstraints()`** | Re-snapping on undo would move the user's element by up to 3 units *as a side effect of undoing*. And the judge stays the only door |
| 5 | History frames are pushed **only when the state actually changed** | `pointerDrag` fires `start` on every click. Without the check, `Ctrl+Z` after a click does nothing, and the user learns the feature is broken |
| 6 | `Ctrl+Z` inside a text box stays the **browser's** undo | Field-level undo is what a typist expects. The text edit lands on our stack as one frame when the caret leaves |
| 7 | **Bold/italic are element-wide from the panel**, selection-scoped from the keyboard | The panel reflects the *element*; a run-level control has nowhere to show a partial state honestly beyond `aria-pressed="mixed"` |
| 8 | **Run size stays element-level** | `normalizeText()` stamps one size on every run. A per-run size picker would round-trip to a single value and look like a renderer bug |
| 9 | History is snapshotted at the **`loadIR()` call site**, not inside it | `test_app.py`'s Node harness executes `loadIR()` verbatim; an unstubbed call inside it is a `ReferenceError` that reads as a broken test |
| 10 | `interactions.js` is untouched | It already forwards `end` on all three primitives. Touching the one file that is deliberately measurement-free is pure downside |
