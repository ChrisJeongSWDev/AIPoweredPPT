+## Original Codex Review WARNING being fixed
+
+> The request correctly sends the selected profile ID, and the server
+> independently validates it against `MODEL_PROFILES`. Issue: after
+> generation, the UI status still displays `CONTEXT.model`, which is the
+> server default profile—not the profile sent in this request. Selecting
+> Opus or a GPT profile can therefore report "from Claude Sonnet 5." The
+> model picker also remains enabled while a request is in flight.
+
+## Changes made

+### `src/aippt/canvas/static/editor.js` (only file actually edited with code changes)
+
+1. **Send the selected profile to the backend** (`generate()`):
+   - Added `var modelSel = $('p-model'); var selectedModel = modelSel ? modelSel.value : (CONTEXT && CONTEXT.default_model);`
+     read right before the fetch, so the value is captured once, at request

+     `#p-model` is locked for the same duration as the Generate button and

+3. **Report the profile that was actually used, not the server default**
